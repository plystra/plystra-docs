## 从这里开始

如果你要把 Plystra 接到现有后端，先看接入指南。它会用真实 API 带你走完整路径：

```text
注册资源类型 -> 创建 Space 和身份链 -> 授权角色 -> 登记资源 -> 调用 authz/check
```

## Plystra v1.0 覆盖范围

<CardGrid stagger>
	<Card title="可解释身份链路" icon="user">
		每次授权决策都会说明是谁通过 `User -> UserMember -> Member -> Space` 这条链路发起行为。
	</Card>
	<Card title="作用域权限" icon="setting">
		权限会按照 `self`、`group`、`group_tree`、`space` 的规则求值；`global` 在 v1.0 中保留但禁用。
	</Card>
	<Card title="资源注册表" icon="document">
		资源类型、动作、映射、风险等级和默认审计策略都会作为受管元数据保存。
	</Card>
	<Card title="追加式审计" icon="open-book">
		允许和拒绝的决策都会写入 trace 快照，即使后续元数据变化，历史解释仍可读。
	</Card>
	<Card title="自托管 Core" icon="rocket">
		PostgreSQL、版本化迁移、Ent schema 检查、Docker Compose 和生产安全 guard 都属于 Core 的交付范围。
	</Card>
	<Card title="受保护 API 面" icon="lock">
		非公开 Core API 需要 Bearer user session with an active admin grant；Data Console 和 metrics 默认关闭。
	</Card>
</CardGrid>
